# Agent 技能自演进方法：按优化范式分类

> 调研时间：2026 年 8 月
> 关键词：LLM Agent、Skill Self-Evolution、优化范式、梯度下降、进化搜索、数据挖掘
> 分类原则：按每种方法背后的**核心算法思想/优化范式**分类，而非按信号来源（Eval/Trace）分类

---

## 一、分类框架总览

所有方法共享同一骨架：**大批量执行/评估 → 信号提取 → 技能改写 → 验证接受**，但每种方法采用的**核心优化范式**不同——这正是决定其训练纪律、稳定性机制和适用场景的根本因素。

| 范式 | 核心思想 | 方法 | 类比来源 |
|---|---|---|---|
| **① 梯度下降同构** | 技能=权重，评估分数→文本梯度(编辑补丁)，LR裁剪/epoch/门控/动量/元学习 | SkillOpt, SkillGrad | 深度学习优化器 |
| **② 进化搜索** | 维护候选种群，Pareto前沿选择，变异+交叉，NL反馈 | GEPA | 进化算法/遗传规划 |
| **③ 多臂老虎机/随机内省** | softmax采样候选，方差分桶聚焦难例，好坏轨迹对比自反思 | SIMBA/DSPy | 多臂老虎机/强化探索 |
| **④ 数据挖掘/对比归纳** | 从大批量轨迹挖掘反复模式，或构造成功/失败对比对提取因果证据 | Trace2Skill, SkillCAT, Memento | 数据挖掘/对比学习 |
| **⑤ 形式化契约** | Design by Contract，前后置条件+不变量，确定性二值验证 | ContractSkill | 软件工程形式化方法 |
| **⑥ 结构化组织** | 分层渐进/补丁版本管理/双形式互验/设计精化/记忆拓扑 | MetaClaw, SkillFlow-Bench, AutoRefine, ABSTRAL, MUSE-Autoskill | 信息检索/版本控制/软件架构 |

> **范式层次**：①②③ 是**优化算法范式**（来自 ML/优化理论，有明确数学对应）；④ 是**数据驱动范式**（来自数据挖掘/统计学习）；⑤⑥ 是**工程范式**（来自软件工程/信息科学）。

---

## 二、各范式详细说明

### 范式①：梯度下降同构 (Gradient Descent Isomorphism)

**核心洞察**：把 Markdown 技能文档当作神经网络的"可训练参数"，完整照搬深度学习训练纪律。

**关键机制**：
- 评估分数 = 损失函数
- 反思分析 = 反向传播
- 编辑补丁(add/del/replace) = 梯度
- 学习率 = 最大编辑数
- 留出集门控 = 验证早停
- epoch间慢更新 = 动量
- 元技能 = 元学习

| 方法 | 引用 | 梯度形式 | 验证机制 | 特色 |
|---|---|---|---|---|
| **SkillOpt** | Yang et al., 2026b (arXiv:2605.23904) | 离散文本编辑补丁 | held-out utility（留出集严格单调门控） | 全套DL纪律：epoch/LR/调度器/慢更新/元技能；6 benchmark×7模型×3 harness=52格全部best/tied-best；GPT-5.5 +23.5分 |
| **SkillGrad** | Wang et al., 2026b | 可微连续梯度 | loss/validation | 结构化包，组件级独立优化；设计显式可微损失，梯度更精确 |

**共性**：信号来源是评估分数，优化对象是技能文档本身，通过迭代改写+门控接受实现进化。

**差异**：SkillOpt 用离散编辑（可解释、有界防过冲），SkillGrad 试图连续化（梯度更精确但需设计可微损失）。

---

### 范式②：进化搜索 (Evolutionary Search)

**核心洞察**：不维护单一最优解，而是维护一个**候选种群**，通过 Pareto 前沿选择 + 变异 + 交叉实现进化。

**关键机制**：
- 候选种群 = 多个并行技能/prompt 版本
- Pareto 前沿选择 = 在任一样本上最强即存活，防早熟收敛
- 变异 = 继承祖先经验做少量改动
- 交叉 = 跨候选合并互补经验
- NL反馈 = 评测函数除分数外还回传自然语言反馈（报错、编译输出、约束违规）

| 方法 | 引用 | 选择策略 | 变异机制 | 特色 |
|---|---|---|---|---|
| **GEPA** | UC Berkeley/Stanford, ICLR 2026 Oral | Pareto 前沿（任一样本最强即存活） | 继承祖先经验 + 跨候选交叉 | 较 GRPO 平均+10%（最高+20%）而rollout少至1/35；较MIPROv2高10%+且prompt短至1/9.2；可作推理期搜索 |

**适用场景**：rollout 昂贵、反馈富文本（如代码优化、ARC 推理）的场景。少量 rollout 也有大增益。

---

### 范式③：多臂老虎机/随机内省 (Multi-Armed Bandit / Stochastic Introspection)

**核心洞察**：用多臂老虎机策略平衡探索/利用，按输出方差聚焦高方差难例，让 LLM 对比好坏轨迹自反思。

**关键机制**：
- softmax 采样候选 = 平衡利用/探索
- 多温度跑轨迹 = 增加样本多样性
- 按输出方差分桶 = 高方差=难例优先，不均匀分配注意力
- 好坏轨迹对比自反思 = 产出具体改进规则或成功 demo
- 双策略：append_a_rule（泛化规则）或 append_a_demo（具体示例）

| 方法 | 引用 | 采样策略 | 难例聚焦 | 特色 |
|---|---|---|---|---|
| **SIMBA/DSPy** | Stanford NLP, 2025–2026 | softmax多臂老虎机采样 | 按输出方差分桶，高方差优先 | 比MIPROv2更样本高效、更稳定；需较强LLM（3B以下可能不如简单优化器）；是GEPA的直接前身 |

**与 GEPA 的关系**：SIMBA 是 GEPA 的前身。GEPA 在 SIMBA 基础上加了 Pareto 前沿 + NL 反馈。

---

### 范式④：数据挖掘/对比归纳 (Data Mining / Contrastive Induction)

**核心洞察**：从大批量执行轨迹中挖掘反复出现的成功/失败模式，或构造成功/失败对比对提取因果关键证据，归纳为技能。

**关键机制**：
- 大批量轨迹采集 = 千级任务执行数据
- 模式挖掘 = 识别反复出现的策略/陷阱
- 对比对构造 = 同任务成功/失败配对，定位因果关键点
- Map-Reduce 合并 = 多轨迹补丁聚合为通用技能

| 方法 | 引用 | 挖掘方式 | 表示形式 | 评估机制 | 特色 |
|---|---|---|---|---|---|
| **Trace2Skill** | Ni et al., 2026 | Map-Reduce 式模式归纳 | L2 markdown | rubric judge | 全自动轨迹→技能转换；离线批量管道 |
| **SkillCAT** | Chen et al., 2026 (arXiv:2606.13317) | 对比因果提取（CCE）：多样本采样，构造成功/失败对比对 | 3层拓扑(domain/task-type/instance) | 评估增强(AAE)：补丁回放校准评分 | +40.40%平均分；解决Trace2Skill的三大问题（单轨迹偏差/未验证合并/上下文过载） |
| **Memento** | Zhou et al., 2026a | 案例提取：从轨迹提取关键决策节点 | markdown + trace(技能+案例绑定) | L3 code gate | 策略+证据双轨存储，可审计 |

**共性**：信号来源是**执行轨迹**（完整推理链+工具调用），优化方式是模式归纳而非梯度下降。

**差异**：
- Trace2Skill：纯归纳（轨迹→新技能），Map-Reduce 批量合并
- SkillCAT：对比归纳（成功/失败对比对→因果证据），回放验证后层级合并，推理期拓扑路由
- Memento：绑定归纳（轨迹→案例附加到技能），不合成新技能而是增强现有技能

**SkillCAT 三阶段详解**：
1. **CCE（对比因果提取）**：每个任务多样本采样多条轨迹，构造同任务成功/失败对比对，提取因果关键证据——解决单轨迹偏差
2. **AAE（评估增强进化）**：候选补丁在源任务克隆上回放，按结果变化赋校准分，只保留改善/持平补丁再层级合并——解决未验证合并
3. **TTE（拓扑感知执行）**：进化后技能编译为可路由能力节点拓扑，推理时只加载相关子集——解决上下文过载

**成绩**：SpreadsheetBench 上 55.50% Vrf（Qwen3.5-35B），较 Trace2Skill +25.83 pp；69.50% Vrf（Qwen3.5-122B）；跨模型和 OOD 泛化均验证。

### 范式⑤：形式化契约 (Formal Contract)

**核心洞察**：从软件工程"设计契约"(Design by Contract)出发，将技能建模为前置条件、后置条件和不变量的形式化集合，用确定性二值验证替代概率性 LLM 判断。

**关键机制**：
- 前置条件(precondition)：执行前必须满足的状态
- 后置条件(postcondition)：执行后必须达到的状态
- 不变量(invariant)：执行过程中必须保持的性质
- 确定性检查：二值判定，无歧义，无需 LLM 参与

| 方法 | 引用 | 技能表示 | 验证方式 | 特色 |
|---|---|---|---|---|
| **ContractSkill** | Lu et al., 2026b | pre/postcondition artifact | deterministic checks | 形式化契约，二值判定；评估成本极低；适用于安全关键场景 |

**独特价值**：唯一不依赖 LLM-as-judge 的方法，评估完全确定性。技能表示是形式化契约而非自然语言，可被机器精确解析和验证。

---

### 范式⑥：结构化组织 (Structural Organization)

**核心洞察**：通过结构化表示（分层/补丁/双形式/设计/记忆）驱动技能的精炼、管理和加载。

**关键机制**（因方法而异）：
- 分层渐进加载：L1摘要→L2概览→L3详情，按需加载
- 增量补丁版本管理：JSON patch + 文件树，可追踪可回滚
- 双形式互验：自然语言+结构化规范，相互校验
- 自顶向下设计：设计文档→SKILL.md，逐层精化
- 记忆拓扑：per-skill memory，持续积累

| 方法 | 引用 | 结构化策略 | 评估机制 | 特色 |
|---|---|---|---|---|
| **MetaClaw** | Xia et al., 2026b | L1/L2/L3 三层渐进加载 | L3 code gate | 三层表示实现"检索→决策→执行"渐进加载；代码级验证 |
| **SkillFlow-Bench** | Zhang et al., 2026j | files + JSON patch 增量版本管理 | benchmark verifier | 补丁形式使演进可追溯可回滚；标准化验证平台 |
| **AutoRefine** | Qiu et al., 2026 | 双形式(NL+结构化规范)协同精炼 | rubric judge | 双形式设计增强可读性与可执行性；互验提供额外保障 |
| **ABSTRAL** | Song et al., 2026a | 设计文档→SKILL.md 自顶向下精化 | trace evidence | 设计先行，确保架构质量；轨迹揭示设计缺陷时回溯 |
| **MUSE-Autoskill** | Lin et al., 2026 | per-skill memory 记忆拓扑 | unit tests | 逐技能记忆持续积累；记忆与策略分离防膨胀；测试可回归 |

**共性**：关注点不在优化算法本身，而在技能的**组织形式、表示结构和管理策略**。

**差异**：MetaClaw 管加载策略，SkillFlow-Bench 管版本追踪，AutoRefine 管表示一致性，ABSTRAL 管设计质量，MUSE 管经验积累。

## 三、范式间对比分析

### 3.1 优化算法范式对比（①②③）

| 维度 | ① 梯度下降同构 | ② 进化搜索 | ③ 多臂老虎机 |
|---|---|---|---|
| **维护对象** | 单一最优技能文档 | 候选种群(多个并行版本) | 候选池 + softmax 选择 |
| **选择策略** | 留出集严格单调门控 | Pareto 前沿(任一样本最强即存活) | softmax 概率采样 |
| **变异机制** | 文本编辑补丁(add/del/replace) | 继承祖先经验 + 跨候选交叉 | 好坏轨迹对比→规则/demo |
| **稳定性来源** | LR裁剪+门控+慢更新 | Pareto 前沿保多样性 | softmax探索+全集终选 |
| **利用信号** | 轨迹反思→有界编辑 | 分数+自然语言反馈 | 好坏轨迹对比→规则/demo |
| **优化对象** | 单份技能文档(部署即交付) | 系统内各模块prompt | 指令规则+few-shot示例 |
| **适用场景** | Agent技能长期演进与迁移 | rollout昂贵、反馈富文本 | 难例集中、需样本高效 |
| **代表方法** | SkillOpt, SkillGrad | GEPA | SIMBA/DSPy |

### 3.2 数据驱动范式对比（④）

| 维度 | Trace2Skill | SkillCAT | Memento |
|---|---|---|---|
| **轨迹利用** | Map-Reduce 批量模式归纳 | 对比因果(CCE)：成功/失败对比对 | 案例提取：关键决策节点绑定 |
| **补丁验证** | 无独立验证(直接合并) | AAE回放校准(改善/持平才合并) | L3 code gate |
| **推理加载** | 全量加载 | TTE拓扑路由(只载相关子集) | 全量+案例 |
| **解决的问题** | 轨迹→技能的基础管道 | 单轨迹偏差/未验证合并/上下文过载 | 策略可审计性 |
| **粒度** | L2 中等粒度 | 3层拓扑(精细) | markdown+trace |

### 3.3 全范式横向对比

| 维度 | ①梯度下降 | ②进化搜索 | ③多臂老虎机 | ④数据挖掘 | ⑤形式化契约 | ⑥结构化组织 |
|---|---|---|---|---|---|---|
| **信号类型** | 评估分数 | 分数+NL反馈 | 方差+轨迹对比 | 执行轨迹 | 确定性条件 | 结构化表示 |
| **信号强度** | 强 | 强 | 中 | 中 | 强(无歧义) | 因方法而异 |
| **冷启动** | 可从空白训起 | 需初始种群 | 需候选池 | 需已有轨迹 | 需定义契约 | 因方法而异 |
| **可复现性** | 高(固定种子) | 中(种群随机) | 中(softmax随机) | 高(离线批量) | 高(确定性) | 因方法而异 |
| **数学根基** | 凸优化/SGD | 进化计算 | 强化学习/老虎机 | 统计学习 | 形式化方法 | 信息科学 |
| **DL对应** | 完全同构 | 种群训练 | 主动学习/难例挖掘 | 数据预处理/特征工程 | 无直接对应 | 架构设计 |

## 四、范式间的演化关系

```
                ┌─────────────────────────────────────────┐
                │         共性骨架                         │
                │  执行/评估 → 信号提取 → 技能改写 → 验证接受  │
                └──────────────┬──────────────────────────┘
                               │
           ┌───────────────────┼───────────────────┐
           │                   │                   │
     优化算法范式          数据驱动范式          工程范式
     (①②③)                (④)                (⑤⑥)
           │                   │                   │
     ┌─────┼─────┐       ┌─────┼─────┐       ┌─────┼─────┐
     │     │     │       │     │     │       │     │     │
    ①     ②     ③       ④           ⑤     ⑥
  梯度   进化  老虎机  数据挖掘    契约   结构化
  下降   搜索          /对比归纳          组织
     │     │     │       │                   │
     │     └──→③前身     │                   │
     │     GEPA继承SIMBA │                   │
     │                   │                   │
     │              SkillCAT继承             │
     │              Trace2Skill              │
     │              (解决三大问题)             │
     │                   │                   │
     └───────────────────┼───────────────────┘
                         │
                    可正交组合:
                    梯度下降(①) + 门控用代码验证(⑤)
                    数据挖掘(④) + 补丁用JSON管理(⑥)
                    进化搜索(②) + 轨迹用对比归纳(④)
```

**关键演化链**：
- SIMBA/DSPy → GEPA：GEPA 在 SIMBA 基础上加 Pareto 前沿 + NL 反馈
- Trace2Skill → SkillCAT：SkillCAT 解决 Trace2Skill 的单轨迹偏差/未验证合并/上下文过载
- SkillOpt 独立路线：完整 DL 训练纪律迁移，不依赖外部轨迹

## 六、实践选型指南

| 需求场景 | 推荐范式 | 推荐方法 | 理由 |
|---|---|---|---|
| 需要**可复现、可调参、可迁移**的基线技能 | ①梯度下降 | SkillOpt | DL训练纪律全套迁移，超参可网格搜，留出集门控保泛化 |

## 七、总结

1. **六种范式覆盖全景**：从 ML 优化理论（梯度下降/进化搜索/多臂老虎机）到数据驱动（数据挖掘/对比归纳）到工程方法（形式化契约/结构化组织），完整覆盖了 Agent 技能自演进的方法空间

2. **优化算法范式有明确数学根基**：①②③ 可分别对应凸优化、进化计算、强化学习，使得超参搜索、收敛性分析、稳定性证明有理论工具可用

3. **数据驱动范式是大数据时代的产物**：④ 类方法依赖大批量执行轨迹，SkillCAT 的对比因果提取代表了从"单轨迹归纳"到"对比因果分析"的方法论进步

4. **工程范式关注表示与管理**：⑤⑥ 类方法不在优化算法上创新，而在技能的表示形式、验证方式和组织策略上发力，是前四类的有力补充

5. **范式可正交组合**：实际工程中，梯度下降(①)的门控可用代码验证(⑤)，数据挖掘(④)的补丁可用JSON管理(⑥)，进化搜索(②)的变异可用对比归纳(④)——混合范式是趋势

6. **均不更新模型权重**：所有方法的共同前提是不碰模型参数，只优化技能文档/制品，部署时零额外推理调用
