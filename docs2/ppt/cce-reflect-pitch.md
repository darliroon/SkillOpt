# CCE-Reflect：对比因果提取反思算子

> 汇报思路：痛点 → 设计 → 预期优化案例

---

## 一、SkillOpt 现有反思机制的痛点

### 1.1 现有流程回顾

SkillOpt 每个训练步的反思阶段（Reflect）将 rollout 结果分为**成功**和**失败**两组，分别交给两个独立的 analyst：

```
40 条 rollout
  ├── 失败 (如 8 条) → analyst_error.md → "为什么错了？"
  └── 成功 (如 32 条) → analyst_success.md → "有什么好模式？"
```

两个 analyst **互不可见**：失败 analyst 看不到成功轨迹，成功 analyst 看不到失败轨迹。

### 1.2 痛点：缺乏对照组，归因靠"猜"

失败 analyst 的输入材料：

| 材料 | 提供什么 | 缺什么 |
|---|---|---|
| 失败轨迹 ×8 | agent 做了什么 | 成功时 agent 做了什么（对照组） |
| 真值答案 (Hidden Reference) | 正确答案是什么 | **哪一步行为是成败分水岭** |
| 当前 skill 全文 | 规范是什么 | 行为是否违反了已有规则 |
| fail_reason | 结果层差异 | **行为层差异的因果归因** |

analyst 只能做 **P(pattern \| fail)** 的相关性分析——"8 条失败里有 5 条都做了 X，所以 X 是问题"。但它**看不到成功轨迹是否也做了 X**。

### 1.3 具体案例：一个简单类比 + 真实数据

#### 类比：考试改卷老师

想象你是一个改卷老师，批了 40 份试卷，8 份不及格、32 份及格。你只能看 8 份不及格的卷子，要找出"为什么不及格"。

你翻了一遍，发现 8 份不及格的卷子里有 5 份都"没写过程只写了答案"。

你的结论：**"没写过程"是不及格的原因。** 你提议加一条规则："必须写过程"。

**但问题是**：那 32 份及格的卷子里，有多少也"没写过程"？如果有 25 份及格的也没写过程——那"没写过程"根本不是不及格的原因，只是这批学生的通用习惯。你加的规则是无效的。

**你看不到及格的卷子，无从得知。**

#### 真实数据（SearchQA step 38）

回到我们的系统。失败 analyst 拿到 8 条失败轨迹，发现其中 5 条的共同模式是：**agent 回答时多加了不必要的修饰词**。

比如问题问"维生素 C 的别名是什么"，正确答案应该是"C"，但 agent 回答了"Vitamin C"——多加了"Vitamin"这个词。

analyst 判定"多加修饰词"是系统性缺陷，提议了一条 skill 补丁。

**核心问题**：那 32 条成功的轨迹里，agent 有没有也"多加修饰词"但碰巧被判对的？

- 如果成功侧也普遍"多加修饰词" → 这只是这类问题的通用答法，不是失败因果，补丁无效
- 如果成功侧很少"多加修饰词" → 确实是因果信号，补丁有效
- **analyst 无从得知**——它看不到成功侧的任何信息

### 1.4 统计证据：Gate 拒绝率

从本次 SearchQA 40 步训练的实际数据：

| 指标 | 值 |
|---|---|
| 总步数 | 40 |
| Accept（接受候选 skill） | 8 步 (20%) |
| Reject（拒绝候选 skill） | 30 步 (75%) |
| Skip（无补丁可生成） | 2 步 (5%) |

**75% 的拒绝率**意味着：analyst 生成的补丁大部分在 gate 评估时被判定为无效甚至有害。核心原因是：**没有对照组，analyst 的归因是相关性而非因果性**，补丁质量不稳定。

## 二、CCE-Reflect 算子设计

### 2.1 核心思想：配对对照实验

CCE-Reflect（Contrastive Causal Extraction）借鉴流行病学的 **matched case-control study**：

```
同一任务跑两次（或同类别配对）：
  任务 A（失败）: 没读表头 → 公式错 → 答错
  任务 A（成功）: 先读表头 → 公式对 → 答对

任务内容完全相同 → 任务间方差 = 0
唯一差异 = 行为 → 因果信号纯净
```

### 2.2 三层改进

| 维度 | SkillOpt 现状 | CCE-Reflect |
|---|---|---|
| **归因粒度** | 结果层（输出 vs 真值） | 行为层（逐步 divergence point） |
| **信号类型** | 相关（P(pattern\|fail)） | 因果（P(pattern\|fail) - P(pattern\|success)） |
| **混杂控制** | 靠 prompt 规则约束 | 靠实验设计自动抵消 |

**1. 行为层归因**：不靠 LLM 猜"哪步关键"，而是机械地找到两条轨迹的第一个行为分叉点（divergence step），分叉之后就是候选因果差异。

**2. 因果差分**：`P(pattern | fail) - P(pattern | success)` 把成功和失败共有的模式（混杂因子）直接消掉。一个模式只有在失败中频繁、在成功中罕见时，才会被判定为因果因子。

**3. 设计消除混杂**：同任务配对 → 任务内容、表格、指令全部相同 → 两条轨迹间的唯一差别就是行为本身。

### 2.3 注入方式：环境无关

```
现有 reflect 流程:
  run_minibatch_reflect()
    ├── analyst_error → 失败 patches
    └── analyst_success → 成功 patches
                                      ↓
                             merge → candidate skill
                             ↓
                           gate 评估

加入 CCE 后:
  run_minibatch_reflect()
    ├── analyst_error → 失败 patches
    ├── analyst_success → 成功 patches
    └── run_cce_reflect → 对比因果 patches  ← 新增
                                      ↓
                             merge → candidate skill
                             ↓
                           gate 评估
```

- CCE patch 与现有 patch 结构完全同构，`_normalise_patches()` 无需改动
- 通过配置开关 `use_cce_reflection: false` 控制，关闭时逐字节与基线一致
- 所有环境自动继承（走通用 reflect 引擎的 = 全部环境）

### 2.4 配对策略：字段回退链

由于当前 rollout 每题只跑一次，真·同任务配对不存在。采用**同类别配对**作为退化方案：

```
配对键回退链:
  task_type → instruction_type → category → domain

同类别内: 失败 × 成功 做最多 M:N 对
每条成功最多被引用 2 次（cce_success_reuse）
每步上限 6 对（成本护栏）
无类别键时静默跳过，不报错
```

### 2.5 成本控制

| 项目 | 现状 | CCE 增量 |
|---|---|---|
| Rollout 调用 | 40 次/步 | **0**（复用已有 rollout） |
| Optimizer 调用 | ~6 次/步 | +2 次（6 对 ÷ 3 对/调用） |
| 额外 wall time | — | <5%（optimizer 并行，rollout 才是瓶颈） |

## 三、预期优化案例

### 3.1 案例一：SearchQA 答案格式问题

**现有 analyst（无对照）**：

改卷老师只能看不及格的卷子。8 份不及格里有 5 份都"多加了修饰词"（比如问"别名是什么"，答了"Vitamin C"而非"C"）。老师判定"多加修饰词"是不及格原因，提议加规则。

但老师看不到及格的 32 份卷子里有没有也"多加修饰词"但碰巧对了的——如果有很多，这条规则就是无效的。

→ Gate 评估：75% 概率被拒绝（因为规则可能确实无效）

**CCE-Reflect（有对照）**：

改卷老师现在能同时看到同一道题的及格卷和不及格卷：

```
同一道题（问"维生素 C 的别名"）:
  不及格卷: agent 答了 "Vitamin C"（多加了修饰词）
  及格卷:   agent 答了 "C"       （只答了别名）

两份卷子题目完全相同 → 唯一差异就是"有没有多加修饰词"
→ 不用猜，直接锁定因果：多加修饰词 = 失败原因
```

进一步统计所有配对：
- "多加修饰词"在失败侧出现 5/8 次
- "多加修饰词"在成功侧出现 2/32 次
- 差分 = 0.56，远大于 0 → 确认是因果因子

CCE 补丁：*"当问题已经给了类别词（如"维生素"），只回答具体的别名/昵称，不要重复类别词"*

→ 因果链明确，Gate 更可能接受

### 3.2 案例二：SpreadsheetBench 多步操作

**现有 analyst（无对照）**：

一个 agent 操作 Excel 表格，走了 30 步，最终公式写错了。analyst 要从 30 步里找出"哪一步导致最终出错"——就像在 30 页的考卷里找一处笔误，只能靠人肉通读猜。

可能猜对，也可能猜错。猜错了就提议了无效补丁，被 gate 拒绝。

**CCE-Reflect（有对照）**：

现在拿同一道表格题的及格轨迹和不及格轨迹**逐步对比**：

```
步骤 1-14: 两条轨迹完全一样（同样的点击、同样的输入）
步骤 15:   分叉了！
             不及格: 直接写 =SUM(A1:A10)  ← 漏了两个单元格
             及格:   先检查了合并单元格，写了 =SUM(A1:A12)

分叉点 = 第 15 步，不需要猜，机械对比就能找到
```

CCE 补丁：*"写 SUM 公式前，先检查目标区域有没有合并单元格"*

→ 精准定位因果步骤，补丁质量高

### 3.3 预期指标改善

| 指标 | 现状（无 CCE） | 预期（加 CCE） | 改善 |
|---|---|---|---|
| Gate 接受率 | 20% | 35-45% | +15-25% |
| 补丁因果质量 | 相关性归因 | 因果差分归因 | 质变 |
| 有效训练步数 | 8/40 | 14-18/40 | +75-125% |
| 额外 rollout 成本 | — | 0 | 无 |
| 额外 optimizer 成本 | — | +33% | 微增 |

### 3.4 CCE 价值最大的场景

1. **无真值环境**：只有二值 reward、没有人类可读 reference 时，现有第一重信号（真值对照）直接失效，CCE 是唯一的行为层归因手段
2. **长程任务**：轨迹 30+ 步时，靠 LLM 通读全轨迹猜关键步很不可靠，逐步 diff 是机械操作，精度远超 LLM 推理
3. **失败集异质**：batch 里失败原因五花八门时，"共性"过滤会把真信号平均掉；配对按任务逐一归因，不受异质性影响

## 四、总结

```
SkillOpt 现状的三重替代信号:
  真值答案 → 结果层对齐（答案是什么）
  批次共性 → 统计过滤（什么是系统性的）
  技能文本 → 规范对照（规则缺了还是没被遵守）

CCE-Reflect 补的洞:
  ✓ 行为层归因 → 不用猜哪步关键，机械 diff 找分叉点
  ✓ 因果性信号 → P(fail) - P(success) 消除混杂因子
  ✓ 方差消减 → 同任务配对，任务间方差归零

代价: 每步 +33% optimizer 调用，0 额外 rollout
收益: Gate 拒绝率下降，有效步数增加，skill 质量提升
```
