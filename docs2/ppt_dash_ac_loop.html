A 全量适配 — 冷启动 / 换新模型时用 DSPy + GEPA 富反馈反思循环
场景: 需从贵模型迁移到便宜模型(如o3→gpt-oss-120b), 手写Prompt直接搬过来质量掉, 人工调1-2周还追不回 → 需全量重写适配
1
GEPA 富反馈生成核心机制
每条"人机评分分歧"生成结构化文本反馈:不再是标量分数, 而是"分差大小+方向+人类解释+模型推理"四维组合
diff = predicted - expected; + human rationale; + model reasoning
2
DSPy 反思循环迭代优化循环
评估→暴露失败模式(自然语言)→Prompt修订→重评→直接优化NMSE → 系统能回应具体模式(如"低估时效性""过度关键词匹配")
3
反过拟合护栏工程保障
禁止拷贝训练集关键词/用户名/文档原文到Prompt(防"背例") · 禁止改任务参数(评分范围/格式定义) · 强制加"通用规则"而非"具体例子"
4
留出集门控验收上线门槛
优化Prompt vs 手写Prompt在留出集上同条件PK → NMSE严格优于基线才接受 → 产出初始优化Prompt 进入生产

C 增量演进 — 生产裁判安全持续微调 指令库 bullet + DSPy 选择组装
场景: 生产裁判已强且多条流水线依赖, 大改风险高(改一词corner case就变) → 不重写整段Prompt, 只做"小PR+测试"式安全增量
1
线上分歧案例涌现信号来源
A产出的裁判线上执行 → 遇到新边界case(如文档时效/模糊匹配) → 裁判打分与人类评分出现显著分歧 → 记录该(查询,文档)对
2
人类写解释 → 蒸馏单行bullet知识沉淀
人类写"该文档超一年应降分" → 压缩为单行规则存入指令库
"Documents older than a year should be rated at least one point lower..."
3
DSPy 选择+组装(非重写)核心机制
DSPy不重写Prompt主体 → 只从指令库中选哪几条bullet加进Prompt末尾、怎么组合 → 在验证集上测是否提分且不引入副作用 → 通过才加
4
"小PR+测试"增量上线安全保障
每条bullet附触发它的分歧案例做验证 → 增量改/回归可诊断/基线行为稳定 → 不回退已有能力的同时持续推高对齐

越用越好闭环:
A: GEPA全量适配产出初始优化Prompt → 生产裁判上线服务三条流水线 → C: 线上分歧案例→人类解释→蒸馏bullet→DSPy选组装→增量上线 → 裁判进化后继续服务→新分歧继续涌现 → ↻ 持续增益
大场景变化时(如换模型)回到A全量重适配
一句话: A用GEPA富反馈全量适配产出初始优化Prompt→部署生产→C持续采分歧案例蒸馏bullet规则DSPy选组装增量微调——A治"从差到好"的大步快跑,C治"从好到更好"的安全增量,两者串联构成"越用越好"闭环 来源: Dropbox Tech Blog (2026.03)
