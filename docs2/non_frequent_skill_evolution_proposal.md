# 面向 Agent 开域场景的非高频 Skill 自演进方案

> 场景：Agent 开域后，面对海量"信息量适中"的非高频任务，需用基于 Eval/Trace 大批量数据的自演进思路，快速构建技能成功率，同时压降时延与 Token 开销

---

## 一、场景定义与挑战

### 1.1 场景描述

当 Agent 从封闭域（如单一垂直任务）走向**开域**（如通用办公助手、开放问答、多场景操作），会面临一种此前被忽视的技能类别——**非高频、信息量适中的 Skill**：

| 维度 | 特征 |
|---|---|
| **频次** | 非高频——每天/每周才触发几次，无法像高频技能那样靠大量执行积累经验 |
| **信息量** | 适中——不是简单的一两条规则能搞定，也不至于需要数千字策略文档 |
| **来源** | Agent 开域后自然涌现——用户问了之前没设计过的新类型任务 |
| **规模** | 数量大——开域后可能有成百上千个这样的技能需求 |
| **冷启动** | 无种子技能、无历史轨迹、无人工标注 |

**典型例子**：Agent 开域后用户问"帮我把这个 PDF 里的表格转成 Excel 并标注异常值"——不是高频任务，但需要中等复杂度的策略（PDF 解析→表格提取→异常判定→Excel 格式化），且这类需求会不断涌现。

### 1.2 核心挑战：三角约束

```
        成功率 ↑
       /        \
      /  张力区   \
     /            \
时延 ↓ ←——⇄——→ Token ↓
```

| 挑战 | 说明 | 为什么难 |
|---|---|---|
| **① 成功率冷启动慢** | 非高频技能没有足够执行数据，无法靠"用多了自然变好"的交互演进积累经验 | 交互演进依赖用户实际触发，非高频技能触发率低，数月也积攒不到有效样本量 |
| **② 朴素训练会膨胀** | 为了提升成功率，最直觉的做法是加规则、加示例、加上下文——技能越写越长 | 长技能 → Token 暴涨 → 推理变慢 → 时延升高，与降时延/降 Token 目标直接冲突 |
| **③ 评测信号弱** | 非高频任务没有标准答案，难以判定技能是否真的变好 | LLM-as-judge 有噪声；没有留出集做统计显著检验；单次执行的成败可能是运气 |
| **④ 技能检索困难** | 开域后技能数量膨胀，全量塞进上下文不现实 | 每个技能几百 token，100 个技能就是几万 token，严重挤占上下文窗口 |
| **⑤ 迁移性要求高** | 非高频技能投入产出比低，必须能跨模型/跨任务复用才值得训练 | 为每个非高频任务单独训练不现实，需要"训练一次，多处复用" |

### 1.3 为什么现有方法不够

| 现有方法 | 局限 |
|---|---|
| **交互演进（少样本在线学习）** | 非高频触发率低，数月积攒不到有效样本量；无 ground truth，无法证伪"变好了" |
| **高频路径固化（Skills→Scripts）** | JIT 编译依赖高频执行路径，非高频技能执行次数不够触发固化 |
| **全量加载** | 开域后技能数膨胀，全量加载导致 Token 爆炸 + 注意力稀释 |
| **人工编写** | 非高频技能数量大，人工逐一编写成本不可接受 |

## 二、关键技术 & 竞争力

### 2.1 核心技术组合

本方案的竞争力来自**三种范式的正交组合**，每种范式解决一个核心痛点：

```
┌─────────────────────────────────────────────────────────┐
│                    非高频 Skill 自演进                      │
│                                                          │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐   │
│  │ 大批量 Eval  │  │  Trace 对比  │  │  结构化加载  │   │
│  │ 离线训练     │  │  归纳        │  │  与精简      │   │
│  │ (梯度下降)   │  │  (数据挖掘)  │  │  (组织范式)  │   │
│  └──────┬───────┘  └──────┬───────┘  └──────┬───────┘   │
│         │                 │                 │            │
│    解决: 成功率冷启动  解决: 信号质量    解决: Token&时延  │
│    (大批量 Eval 替代   (对比因果提取替   (精简+分层加载    │
│     少样本交互)         代单轨迹归纳)    替代全量塞入)     │
│         │                 │                 │            │
│         └────────┬────────┘                 │            │
│                  ↓                          │            │
│         ┌────────────────┐                  │            │
│         │ 训练产出:       │←─────────────────┘            │
│         │ 精简可迁移的    │                               │
│         │ best_skill.md  │                               │
│         └────────────────┘                               │
└─────────────────────────────────────────────────────────┘
```

| 技术模块 | 解决的痛点 | 选用范式 | 关键机制 |
|---|---|---|---|
| **A. 大批量 Eval 离线训练** | 成功率冷启动慢 | 梯度下降同构 | 离线批量执行 → Reflect → 编辑补丁 → 留出集门控；空白技能从零训起 |
| **B. Trace 对比因果归纳** | 评测信号弱、单轨迹偏差 | 数据挖掘/对比归纳 | 多温度采样构造成功/失败对比对 → 提取因果关键证据 → 补丁回放校准 |
| **C. 结构化精简与按需加载** | Token 膨胀、时延升高 | 结构化组织 | 核心规则常驻 + 非核心渐进展开 + 推理期只载相关子集 |

### 2.2 各技术模块详解

#### 模块 A：大批量 Eval 离线训练（成功率快速构建）

**为什么用梯度下降同构范式**：
- 非高频技能冷启动无历史数据，但可以用**标准 benchmark 或合成任务集**做大批量离线执行，人为制造训练信号
- DL 训练纪律（epoch/LR/门控/慢更新）保证可复现、可调参、防过拟合
- 产物是一份紧凑的 best_skill.md（300–2000 token），部署零额外推理调用

**关键机制**：
1. **任务合成**：对非高频技能，用 LLM 合成/扩增任务集（从任务描述生成千级变体）
2. **批量 Rollout**：目标模型用当前技能执行合成任务集，收集轨迹+分数
3. **Reflect 反思**：优化器分析 minibatch 轨迹，识别共性失败模式，产出 add/del/replace 编辑补丁
4. **LR 裁剪 + Select**：学习率限制每步最多改 L 条，防过冲
5. **留出集门控**：新技能在留出验证集上严格优于当前才接受，否则回滚
6. **慢更新 + 元技能**：Epoch 间防遗忘 + 累积"哪些编辑有效"的优化器记忆

#### 模块 B：Trace 对比因果归纳（信号质量提升）

**为什么用数据挖掘/对比归纳范式**：
- 非高频任务的评测信号弱（没有标准答案），单次执行成败可能是运气
- 多温度采样 + 成功/失败对比对能提取**因果关键证据**，而非笼统总结
- 补丁回放校准确保每条改进在源任务上确实有效，避免噪声补丁污染技能

**关键机制**：
1. **多温度采样**：对每个合成任务，用不同温度多次执行，产生多样结果
2. **对比对构造**：同一任务的成功轨迹 vs 失败轨迹配对
3. **因果证据提取**：对比分析成功/失败的**分叉点**——哪个决策导致结果不同
4. **补丁回放校准**：候选编辑补丁在源任务克隆上回放，按结果变化赋校准分
5. **只保留改善/持平补丁**：低质量/有害补丁被过滤后再进入训练循环

#### 模块 C：结构化精简与按需加载（Token & 时延压降）

**为什么用结构化组织范式**：
- 梯度下降训练可能产出过长技能（朴素地"加规则提成功率"会膨胀）
- 需要在训练过程中和训练后都保持技能精简
- 开域后技能数量多，需按需加载而非全量塞入

**关键机制（三道精简关卡）**：

| 关卡 | 时机 | 机制 | 效果 |
|---|---|---|---|
| **训练期精简** | 每次 Update 前 | LR 限制编辑数 + del 操作主动删冗余规则 + 聚合合并语义重复补丁 | 防止技能在训练中无限膨胀 |
| **训练后去膨胀** | 训练完成后 | 分类学切片：核心规则常驻，示例/背景转渐进式按需展开 | 技能保持最小可用形态 |
| **推理期按需加载** | 部署运行时 | 技能分解为能力节点拓扑，推理时只加载任务相关子集 | Token 用量降 90%+ |

### 2.3 竞争力总结

| 竞争力 | 具体体现 | 对比优势 |
|---|---|---|
| **冷启动能力强** | 从空白技能 + 合成任务集从零训出可用技能 | 交互演进做不到；人工编写成本高 |
| **信号质量高** | 对比因果提取 + 补丁回放校准，过滤噪声补丁 | 单轨迹归纳/LLM-as-judge 有噪声 |
| **三角同时优化** | 训练提成功率，去膨胀降 Token，按需加载降时延 | 朴素训练只管成功率，Token 和时延会恶化 |
| **可复现可调参** | 固定数据集+固定种子，可网格搜 LR×调度器 | 交互演进无法重跑，不可调参 |
| **可迁移复用** | 训练一次跨模型/跨 Harness/跨相邻任务直接复用 | 非高频技能投入产出比低，必须能复用才值得 |
| **部署零额外开销** | 产物是一份精简 markdown，推理时按需加载 | 不增加模型调用、不改模型权重 |

### 3.2 流程各阶段说明

#### 阶段一：离线训练（构建成功率）

| 步骤 | 输入 | 操作 | 输出 | 范式 |
|---|---|---|---|---|
| 1. 任务合成 | 技能描述 + 领域知识 | LLM 生成千级任务变体，铺满任务空间 | 合成任务集 | — |
| 2. 批量执行 | 当前技能 + 合成任务集 | 目标模型多温度执行，收集轨迹+分数 | 批量轨迹 | 前向传播 |
| 3. 对比因果提取 | 批量轨迹 | 构造同任务成功/失败对比对，提取因果关键证据 | 因证补丁（候选） | 数据挖掘④ |
| 4. 补丁回放校准 | 候选补丁 + 源任务克隆 | 补丁回放，按结果变化赋校准分，过滤有害补丁 | 校准补丁 | 数据挖掘④ |
| 5. Reflect 反思 | 校准补丁 + 轨迹 | 优化器归纳共性模式，产出结构化编辑补丁 | 编辑补丁(add/del/replace) | 反向传播 |
| 6. Aggregate 聚合 | 多组编辑补丁 | 语义相似补丁层级合并去冗余 | 合并补丁 | 梯度聚合 |
| 7. Select 选择 | 合并补丁 | 按影响排序，LR 限制每步最多 L 条 | Top-L 编辑 | 梯度裁剪 |
| 8. Update 更新 | Top-L 编辑 + 旧技能 | 应用编辑到技能文档 | 新版本技能 | SGD step |
| 9. Gate 门控 | 新技能 + 留出验证集 | 严格优于当前才接受，否则回滚 | 接受/拒绝 | 验证早停 |
| *(Epoch)* | 跨轮次 | 慢更新防遗忘 + 元技能累积策略记忆 | 稳定收敛 | 动量+元学习 |

#### 阶段二：精简与部署（压降 Token & 时延）

| 步骤 | 输入 | 操作 | 输出 | 效果 |
|---|---|---|---|---|
| 10. 训练后去膨胀 | best_skill.md (原始) | 分类学切片：核心规则常驻，示例/背景转渐进展开 | 精简技能 | Token ↓ 30–50% |
| 11. 拓扑化拆分 | 精简技能 | 拆为能力节点拓扑（domain→task-type→instance 三层） | 可路由技能拓扑 | 按需加载基础 |
| 12. 部署按需加载 | 技能拓扑 + 用户请求 | 默认只暴露摘要（~100 token），命中才拉相关子集 | 精准上下文 | Token ↓ 90%+ |

### 3.3 三角约束的解决路径

```
                    成功率 ↑
                   ╱        ╲
            ┌─────╳    路径1   ╲
            │    ╱  大批量Eval   ╲
            │   ╱  离线训练      ╲
            │  ╱  (梯度下降同构)   ╲
            │ ╱                    ╲
            │╱                      ╲
时延 ↓ ←────┼────────────────────────→ Token ↓
            │╲                      ╱
            │ ╲                    ╱
            │  ╲  路径2+3         ╱
            │   ╲  去膨胀+按需   ╱
            │    ╲  加载(结构化) ╱
            └─────╲────────────╱
                    路径2+3
```

| 路径 | 解决什么 | 怎么做 | 副作用控制 |
|---|---|---|---|
| **路径1** | 成功率 ↑ | 大批量 Eval 离线训练，梯度下降同构，留出集门控 | LR 裁剪 + 去膨胀控制技能长度，防止成功率↑ 导致 Token↑ |
| **路径2** | Token ↓ | 训练后去膨胀（分类学切片，核心常驻+非核心按需） | 忠实性检查验证压缩后不丢功能 |
| **路径3** | 时延 ↓ + Token ↓ | 推理期拓扑化按需加载，只载相关子集 | 技能摘要保证检索准确，避免漏载关键技能 |

**关键张力打破点**：传统思路提升成功率靠"加规则加示例"→技能变长→Token和时延恶化。本方案的打破方式是：
- 训练期用 LR 裁剪 + del 操作 + 聚合合并**主动控制技能长度**
- 训练后用分类学切片**分离核心与非核心**
- 推理期用拓扑路由**只加载相关子集**
- 三个环节协同，使成功率↑的同时 Token↓ 和时延↓

## 四、预期效果

| 指标 | 预期提升 | 来源 |
|---|---|---|
| 成功率 | 空白技能 → 可交付水平（+15~25 分） | 大批量 Eval 离线训练 |
| Token 开销 | 较全量加载降 90%+ | 拓扑化按需加载 |
| 时延 | 推理上下文缩短 → 推理轮次减少 → 端到端时延降 | 技能精简 + 按需加载 |
| 技能长度 | 产物 300–2000 token（精简后） | 去膨胀 + 分类学切片 |
| 冷启动速度 | 合成任务集 + 离线训练，不依赖线上触发 | 任务合成 + 批量执行 |
| 迁移性 | 跨模型/跨 Harness/跨相邻任务复用 | 留出集门控保泛化 |
