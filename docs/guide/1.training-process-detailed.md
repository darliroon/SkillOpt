# SkillOpt 训练过程详解

SkillOpt 的核心思想：**优化自然语言 skill 文档与训练神经网络遵循相同的结构**。"被优化的参数"不是权重矩阵，而是一份 Markdown 技能文档。整个训练循环复刻了深度学习的训练范式。

***

## 一、入口与配置

### 入口脚本

`scripts/train.py` 是统一入口：

```bash
python scripts/train.py --config configs/searchqa/default.yaml
```

它完成三件事：

1. **解析 CLI** — `parse_args()` 支持 `--cfg-options section.key=value`（结构化）与旧式 `--key value`（扁平）两种覆盖方式
2. **加载配置** — `load_config()` 读取 YAML、解析 `_base_` 继承、应用 CLI 覆盖、推断后端/模型、生成输出目录
3. **构建并运行训练器** — 通过环境注册表实例化 Adapter，交给 `ReflACTTrainer`

### 配置系统

`skillopt/config.py` 支持两种格式：

- **结构化**（新）：分为 `model` / `train` / `gradient` / `optimizer` / `evaluation` / `env` 六大节，支持 `_base_` 继承
- **扁平**（旧）：所有键在顶层，向后兼容

基线配置在 `configs/_base_/default.yaml`，各环境继承它。例如 `configs/searchqa/default.yaml`：

```yaml
_base_: ../_base_/default.yaml
env:
  name: searchqa
  skill_init: skillopt/envs/searchqa/skills/initial.md
  split_mode: split_dir
  split_dir: data/searchqa_split
train:
  train_size: 400
  batch_size: 40
```

`flatten_config()` 最终将结构化配置压平为 trainer 期望的扁平字典。

## 二、双模型架构

SkillOpt 采用 **Optimizer / Target 双模型**分离架构：

| 角色                   | 配置键                                     | 职责                               |
| -------------------- | --------------------------------------- | -------------------------------- |
| **Optimizer**（优化器模型） | `optimizer_model` / `optimizer_backend` | 分析轨迹、生成 edit patches、合并/重写 skill |
| **Target**（目标模型）     | `target_model` / `target_backend`       | 用当前 skill 执行任务（rollout），是被训练的对象  |

支持的后端：`openai_chat`、`azure_openai`、`claude_chat`、`codex_exec`、`claude_code_exec`、`cursor_exec`、`qwen_chat`、`minimax_chat` 等。

***

## 三、环境适配器（EnvAdapter）

`skillopt/envs/base.py` 定义了抽象接口 `EnvAdapter`，将训练器与环境解耦。每个 benchmark 实现一个子类：

| 方法                                     | 职责                    |
| -------------------------------------- | --------------------- |
| `setup(cfg)`                           | 一次性初始化（加载数据等）         |
| `get_dataloader()`                     | 返回任务数据加载器             |
| `build_train_env(batch_size, seed)`    | 构建训练环境                |
| `build_eval_env(env_num, split, seed)` | 构建评估环境                |
| `rollout(env, skill, out_dir)`         | 用当前 skill 执行任务，返回结果列表 |
| `reflect(results, skill, out_dir)`     | 分析轨迹生成 edit patches   |
| `get_task_types()`                     | 返回任务类型列表              |

已注册环境：`alfworld`、`searchqa`、`livemathematicianbench`、`spreadsheetbench`、`docvqa`、`officeqa` 等。

## 四、训练循环（6 阶段 ReflACT Pipeline）

核心实现在 `skillopt/engine/trainer.py` 的 `ReflACTTrainer.train()`。

### 整体结构

```
for epoch in 1..num_epochs:
    for step in 1..steps_per_epoch:
        ① Rollout   — Target 用当前 skill 执行任务
        ② Reflect   — Optimizer 分析轨迹，生成 edit patches（梯度）
        ③ Aggregate — 层级合并相似 patches
        ④ Select    — 排序 + 按学习率裁剪（梯度裁剪）
        ⑤ Update    — 将选中 patches 应用到 skill 文档
        ⑥ Gate      — 在 selection 集上验证，accept/reject
    # Epoch 边界机制：
    Slow Update — 跨 epoch 纵向对比（动量）
    Meta Skill  — 跨 epoch 优化器策略记忆（元学习）
# 训练结束后：baseline / best / final 在 test 集上评估
```

### 初始化阶段

1. **Adapter setup** + 获取 dataloader
2. **配置双模型后端** — 根据 `backend` 推断 `optimizer_backend` / `target_backend`，设置 deployment、reasoning effort 等
3. **加载初始 skill** **`S_0`** — 来自 `skill_init` 指向的 `.md` 文件（如 searchqa 的初始 skill 几乎为空）
4. **计算训练参数**：
   - `steps_per_epoch = ceil(train_size / (batch_size * accumulation))`
   - `total_steps = num_epochs * steps_per_epoch`
5. **构建 LR 调度器** — `build_scheduler(mode, max_lr, min_lr, total_steps)`
6. **断点恢复检查** — 从 `runtime_state.json` 或 `history.json` 恢复 `current_skill` / `best_skill` / 分数
7. **Baseline 评估** — 用 `S_0` 在 selection 集（`valid_seen`）上跑一次，得到初始分数

***

### 阶段 ① Rollout（前向传播）

> 类比：`predictions = model(input, weights)`

```python
rollout_results = adapter.rollout(train_env, current_skill, rollout_dir, use_eval_feedback=True)
r_hard, r_soft = compute_score(rollout_results)
```

- **Target 模型**用当前 skill 文档作为 prompt 的一部分，执行 `batch_size` 个任务
- 每个任务产生一条轨迹 + 评分（`hard` = 精确匹配 0/1，`soft` = F1 等部分分数）
- 若 `accumulation > 1`，此阶段会跑 `accumulation` 个 batch，patches 累积后统一处理（梯度累积）

**以 searchqa 为例**：Target 收到 skill + question + context，用 `<answer>...</answer>` 输出答案，再用 `evaluator.py` 计算 EM/F1。

***

### 阶段 ② Reflect（反向传播 → 梯度）

> 类比：`gradients = loss.backward()` → edit patches

```python
raw_patches = adapter.reflect(rollout_results, current_skill, batch_dir, ...)
```

- **Optimizer 模型**分析失败（和成功）轨迹的 minibatch，产出结构化的 **edit patches**（对 skill 文档的修改建议）

```Python
# reflect.py L537-L538
# 先按单条轨迹的 hard 分数分流
failures = [r for r in results if not r.get("hard") or float(r.get("hard", 0)) < 1e-9]
successes = [r for r in results if r.get("hard")] if not failure_only else []

# 再把同类轨迹分成 minibatch
fail_batches = _split_minibatches(failures, minibatch_size)   # 全是失败的组
succ_batches = _split_minibatches(successes, minibatch_size)  # 全是成功的组
```

<br />

- 默认实现在 `skillopt/gradient/reflect.py` 的 `run_minibatch_reflect()`：
  - 轨迹按 `minibatch_size` 分组，每组一起分析（小批量 SGD vs 逐样本 SGD）
  - 失败 minibatch 调用 error analyst prompt，成功 minibatch 调用 success analyst prompt（除非 `failure_only=true`）
  - `analyst_workers` 控制并行度（数据并行）

### 阶段 ③ Aggregate（梯度聚合）

> 类比：梯度聚合 / AllReduce

```python
merged_patch = merge_patches(current_skill, all_failure_patches, all_success_patches,
                             batch_size=merge_bs, ...)
```

- 独立生成的 patches 通过**层级 LLM 调用**合并为一个连贯的 patch
- 失败驱动的 patches 优先于成功驱动的
- 每 `merge_batch_size` 个 patch 一组合并，递归直到剩一个
- 失败时回退为简单拼接

***

### 阶段 ④ Select（梯度裁剪 + 学习率）

> 类比：`selected = top_k(gradients, k=learning_rate)`

```python
edit_budget = scheduler.step()            # 或 decide_autonomous_learning_rate()
ranked_patch = rank_and_select(current_skill, merged_patch, max_edits=edit_budget, ...)
```

- `rank_and_select()`（`optimizer/clip.py`）按相关性给 edits 排序，截取前 `edit_budget` 个
- **学习率** = `edit_budget` = 每步最多应用的 edit 数量
- 三种 LR 控制模式（`lr_control_mode`）：

| 模式           | 行为                                   |
| ------------ | ------------------------------------ |
| `fixed`      | 调度器（cosine/linear/constant）决定 budget |
| `autonomous` | Optimizer LLM 自主决定 budget            |
| `none`       | 用于 full\_rewrite 模式，跳过裁剪             |

- LR 调度器类型：

| 调度器          | 行为                        |
| ------------ | ------------------------- |
| `constant`   | 固定 edit\_budget           |
| `linear`     | 线性衰减到 min\_learning\_rate |
| `cosine`     | 余弦退火                      |
| `autonomous` | 由 LLM 自主决策                |

***

### 阶段 ⑤ Update（参数更新）

> 类比：`weights += lr * gradients` → `skill += selected_edits`

根据 `skill_update_mode` 分三种路径：

| 模式                         | 行为                                                            |
| -------------------------- | ------------------------------------------------------------- |
| `patch`                    | `apply_patch_with_report()` 将 edits 应用到当前 skill，生成候选 skill    |
| `rewrite_from_suggestions` | `rewrite_skill_from_suggestions()` 让 Optimizer 基于建议整体重写 skill |
| `full_rewrite_minibatch`   | 直接从 minibatch 候选中选取一个完整重写的 skill                              |

产物 `candidate_skill` 保存到 `candidate_skill.md`。

***

### 阶段 ⑥ Gate（验证集门控）

> 类比：validation-based model selection / early stopping

```python
# 在 selection 集（valid_seen）上评估候选 skill
sel_results = adapter.rollout(sel_env, candidate_skill, sel_eval_dir)
cand_hard, cand_soft = compute_score(sel_results)

gate = evaluate_gate(candidate_skill, cand_hard, current_skill, current_score,
                      best_skill, best_score, ...)
```

- **门控决策**（`evaluate_gate()`）是纯函数：

| 条件                           | 动作                | 含义          |
| ---------------------------- | ----------------- | ----------- |
| `cand_score > best_score`    | `accept_new_best` | 接受并更新 best  |
| `cand_score > current_score` | `accept`          | 接受但不破纪录     |
| 否则                           | `reject`          | 回退到当前 skill |

- 三种比较指标（`gate_metric`）：

| 指标      | 计算方式                  |
| ------- | --------------------- |
| `hard`  | 精确匹配准确率               |
| `soft`  | F1 / 部分分数             |
| `mixed` | `(1-w)*hard + w*soft` |

- `use_gate=false` 时仍跑验证但**强制接受**每个候选
- **selection cache**：按 skill 哈希缓存评估结果，避免重复 rollout
- 可选 **semantic density** 加分：统计 skill 中高影响词（MUST/NEVER/ALWAYS...）的密度，作为 gate score 的微小加项

***

### Step 缓冲区

每个 step 的失败模式和被拒绝的 edits 会被记录到 `step_buffer`，作为后续 step 反思阶段的上下文，避免重复无效编辑。

***

## 五、Epoch 边界机制

### Slow Update（动量 / 纵向对比）

> 类比：Momentum — 抵抗跨 epoch 的灾难性遗忘

从 epoch 2 开始，每个 epoch 结束时：

1. 取上一 epoch 最后一步的 skill（`prev_skill`）和当前 skill（`curr_skill`）
2. 在同一批训练样本（`slow_update_samples` 个）上分别 rollout
3. 构建**纵向对比对**，分四类：

| 类别                | 含义           |
| ----------------- | ------------ |
| `improved`        | 上一轮错、本轮对     |
| `regressed`       | 上一轮对、本轮错（重点） |
| `persistent_fail` | 持续失败         |
| `stable_success`  | 持续成功         |

1. Optimizer 分析这些对比，生成高层**指导**注入 skill 的 `<!-- SLOW_UPDATE -->` 区域
2. 接受方式由 `slow_update_gate_with_selection` 控制：

| 模式          | 行为                                                    |
| ----------- | ----------------------------------------------------- |
| `false`（默认） | force-accept：无条件注入到 `current_skill`（不影响 `best_skill`） |
| `true`      | gated：在 selection 集上验证，过门才接受                          |

1. `longitudinal_pair_policy` 控制保留哪些对比对：`mixed`（全部）/ `changed`（仅 improved+regressed）/ `unchanged`（仅 persistent\_fail+stable\_success）

***

### Meta Skill（元学习 / 优化器记忆）

> 类比：Meta-learning — 优化器跨 epoch 的策略记忆

从 epoch 2 开始：

1. Optimizer 对比前后两个 epoch 的 skill 与表现
2. 写一份紧凑的 **meta-skill 记忆**（高层策略笔记）
3. 下一 epoch 的 Reflect / Aggregate / Select 阶段会把上一 epoch 的 meta-skill 作为额外上下文传入

***

## 六、训练后评估

当 `eval_test=true` 时，在 test 集（`valid_unseen`）上评估三个 skill：

| 技能                 | 含义                           |
| ------------------ | ---------------------------- |
| **S\_0**（baseline） | 初始 skill，未经训练                |
| **best-on-val**    | 训练中 selection 分数最高的 skill    |
| **final/last**     | 训练轨迹最后一步的 skill（可能与 best 不同） |

在 final skill 与 best skill 不同时，会先对 final skill 做一次 selection 验证，若优于 best 则提升为 best（promote 机制）。

最终输出 `summary.json`，记录：

- baseline / best / final 的 test 分数及 delta 提升
- token 消耗统计
- 每 epoch 的 accept/reject/skip 统计
- 总 wall time

## 十、超参数经验法则

根据实验，以下 DL 直觉在 SkillOpt 中成立：

**有效迁移：**

- Cosine 调度 > constant — 与 DL 中一致，余弦退火有助于收敛
- 适中 LR（4-16）> 过高/过低 — edit 太少学习慢，太多噪声大
- Slow Update 有帮助 — 纵向对比防止跨 epoch 灾难性遗忘
- Meta Skill 记忆改善反思 — Optimizer 受益于跨 epoch 策略笔记

**不迁移：**

- Batch size ≠ 越大越好 — 更大的 rollout batch 因 API 成本收益递减
- 更多 epoch ≠ 更好 — skill 比神经网络收敛更快（通常 2-4 epoch 足够）
