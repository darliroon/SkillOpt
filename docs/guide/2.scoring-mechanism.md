# 评分机制：compute_score 详解

## 核心函数

[skillopt/utils/scoring.py](file:///c:/Users/huawei/Desktop/SkillOpt/SkillOpt/skillopt/utils/scoring.py) 中的 `compute_score` 是**环境无关**的聚合层——只做平均：

```python
def compute_score(results: list) -> tuple[float, float]:
    hard = sum(float(r.get("hard", 0)) for r in results) / len(results)
    soft = sum(float(r.get("soft", 0.0)) for r in results) / len(results)
    return hard, soft
```

从每条 rollout 结果中取 `hard` 和 `soft` 两个字段，求算术平均。真正的评分逻辑在各环境的 rollout 里完成，写入这两个字段。

## 两个评分维度

| 字段 | 含义 | 值域 |
|------|------|------|
| `hard` | **严格指标** — 全对才算对 | 通常 0 或 1 |
| `soft` | **宽松指标** — 部分匹配也给分 | 0.0 ~ 1.0 连续 |

## 各环境评分定义

| 环境 | hard | soft | 本质指标 |
|------|------|------|----------|
| **searchqa** | EM (精确匹配 0/1) | F1 (token 级) | SQuAD 式阅读理解 |
| **officeqa** | EM (0/1) | F1 | 同 searchqa |
| **livemathematicianbench** | EM (0/1) | F1 | 同 searchqa |
| **alfworld** | 游戏胜利 (0/1) | 同 hard | 二元任务成功 |
| **spreadsheetbench** | 全部测试用例通过 (0/1) | 通过率 n_pass/n_cases | 代码/公式执行 |
| **docvqa** | ANLS >= 0.999 (0/1) | ANLS 原始分 | 文档视觉问答 |

## 各环境代码示例

### searchqa / officeqa / livemathematicianbench（阅读理解类）

```python
result["hard"] = int(eval_result["em"])   # 精确匹配：归一化后完全相等=1
result["soft"] = eval_result["f1"]        # F1：token 级部分匹配
```

归一化步骤（SQuAD 惯例）：
- 小写化
- 去标点
- 去冠词 (a / an / the)
- 压缩空白

### alfworld（交互游戏类）

```python
result["hard"] = 1 if won else 0          # 赢了=1
result["soft"] = 1.0 if won else 0.0      # 无部分分，和 hard 一样
```

### spreadsheetbench（代码执行类）

```python
result["soft"] = n_pass / n_cases         # 通过率：3/5 个用例对 = 0.6
result["hard"] = 1 if n_pass == n_cases else 0  # 全通过才算 1
```

### docvqa（文档问答类）

```python
result["hard"] = int(eval_result["anls"] >= 0.999)  # ANLS 几乎完美才算对
result["soft"] = eval_result["anls"]                 # Levenshtein 相似度连续值
```

## 在训练器中的使用

trainer 在三个地方调用 `compute_score`：

```python
# 1. Rollout 后计算训练集分数
r_hard, r_soft = compute_score(rollout_results)

# 2. Gate 阶段计算候选 skill 的 selection 分数
cand_hard, cand_soft = compute_score(sel_results)

# 3. 训练后评估 test 分数
test_hard, test_soft = compute_score(test_results)
```

门控阶段（Gate）用哪个分数做 accept/reject 决策，由 `gate_metric` 配置控制：

- `hard` — 用精确匹配率做门控
- `soft` — 用部分匹配率做门控
- `mixed` — 加权混合两者

## 总结

`compute_score` 是一个**统一的聚合层**：不管什么环境，只要 rollout 结果里有 `hard` 和 `soft` 两个字段，它就能求平均返回 `(hard_score, soft_score)`。环境的差异性完全封装在各 adapter 的 rollout 逻辑中——每个环境根据自己的任务性质，自行决定"什么算全对"（hard）和"什么算部分对"（soft）。
